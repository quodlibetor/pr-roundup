# pr-roundup

A local web page that lists your open pull requests, lets you tag them, and
copies each tag's pull requests to the clipboard as a list for Slack so you
can beg people to review your code:

- Tagging a pull request moves it into that tag's section, along with the
  rest of its stack, apart from pull requests that have a different tag. A
  pull request has at most one tag; clearing the field (or `×`) removes it
  from that one pull request.
- A tagged pull request stays in its section after it merges or closes, until
  the tag is removed. Untagged ones disappear when they stop being open.
- Within a section, pull requests are grouped by repository, and each
  repository's pull requests into stacks: GitHub's own stacks first, then
  chains where one pull request's base branch is another's head. Drag a
  repository's heading to reorder repositories within the section.
- GitHub is polled when the server starts and when the page is opened or
  regains focus, at most once per `min_refresh_secs` (a minute by default);
  "Refresh now" polls regardless. Results are pushed to open tabs over
  server-sent events. A live update waits while you are typing a tag.

> LLM notice: entirely generated by claude code, use it if you want 🤖🤨

## Installation

Run a script from the [most recent release][latest], or using homebrew
`homebrew install quodlibetor/tap/pr-roundup`. Or using [mise][]: `mise use -g
github:quodlibetor/pr-roundup@latest`.

[latest]: https://github.com/quodlibetor/sanic-review/releases/latest
[mise]: https://mise.jdx.dev/

## Usage

### Running the web server

```sh
pr-roundup init    # writes ~/.config/pr-roundup/config.toml
$EDITOR ~/.config/pr-roundup/config.toml
pr-roundup --open       # alias for: pr-roundup serve
```

Serving without a config file runs `init` instead. The server won't start
until `repos` or `orgs` lists something to search.

The GitHub token comes from `$GITHUB_TOKEN`, or `gh auth token` when that is
unset. Tags and repository order live in
`$XDG_DATA_HOME/pr-roundup/tags.db`.

### Tagging from the command line

This is mostly for LLMs, use `pr-roundup install-skill` to give them the
instructions.

```sh
pr-roundup tags list
pr-roundup tags set lacework/services#123 "some tag"   # or a pull request URL
pr-roundup tags unset https://github.com/lacework/services/pull/123
pr-roundup tags rename "some tag" "better name"        # merges into a tag in use
```

`set` tags the rest of the pull request's stack too, as tagging on the page
does. These write to the database directly, so the server needn't be running; a
running one updates its page. `pr-roundup install-skill` installs a Claude
Code skill, under `~/.claude/skills/pr-roundup/`, that teaches agents to tag
the pull requests they open; its source is
`.claude/skills/pr-roundup/SKILL.md`.

## Configuration

### Slack emoji

Each status is written into the copied text as configured under `[emoji]` in
the config file, which must set every status. Slack shortcodes such as
`:git-merged:` for custom emoji become emoji when the message is sent; the
page itself always shows Unicode icons.

## Development

Tools are pinned in `mise.toml` and Rust in `rust-toolchain.toml`.
`mise run check` runs formatting, clippy, the tests, and a check that the
release workflow is current.

### Releases

`.github/workflows/release.yml` is generated by dist from
`dist-workspace.toml`; change the config and regenerate rather than editing
the workflow. dist writes to the git root, which from a jj workspace is the
main checkout, so run it from the workspace root as:

```sh
GIT_CEILING_DIRECTORIES="$(realpath ../..)" dist generate
```

Pushing a `vX.Y.Z` tag that matches the version in `Cargo.toml` builds the
release, publishes it on GitHub, and updates the Homebrew formula in
`quodlibetor/homebrew-tap`.
